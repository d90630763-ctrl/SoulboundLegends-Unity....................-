# SL Live Update System — Final Standalone Package

This package provides the live-content foundation for SL. It is intentionally provider-agnostic: the game can use an HTTP/CDN backend, a local folder for development, or a future server service through `IUpdateProvider`.

## Included
- Versioned manifests and schema versioning
- Client/server compatibility checks
- Mandatory/optional updates
- Rollout percentage / canary cohorts
- Staged release states
- Dependency fields
- SHA-256 integrity validation
- Size validation
- Safe path validation
- Temporary download files
- Backup state and automatic rollback on failed installation
- Persistent installed-version state
- Hot-apply/restart-required/client-update-required modes
- Update progress/events
- Feature flags through configuration JSON
- Local provider for offline/editor testing
- HTTP provider for CDN/server delivery
- Unity editor manifest generator
- No hard dependency on a specific backend vendor

## Important architecture truth
Remote data cannot safely replace arbitrary executable Unity code. Content/data can be made live-updateable; major code, engine, native plugin, networking-stack, shader, or structural changes can still require a client build. `ClientPatch` exists to make that boundary explicit rather than pretending otherwise.

## Basic setup
1. Import the folder into `Assets/`.
2. Create a GameObject named `SL Live Update System`.
3. Add `SLLiveUpdateSystem`.
4. Set Game ID and client version.
5. Set the HTTPS manifest base URL when a backend/CDN is available.
6. During development, call `SetProvider(new LocalUpdateProvider(folderPath))` from your bootstrap/test harness.
7. Other systems read `State.configJson` or subscribe to `LiveUpdateEvents`.

## Integration rule
Game systems should keep their normal authoritative logic. The Live Update System supplies validated content/configuration; server-authoritative gameplay remains authoritative on the server. Do not allow a client-only live config to decide security-sensitive actions such as inventory grants, currency, combat results, ownership, or permissions.

## Manifest example
The editor menu `SL > Live Update > Create Example Manifest` creates a development manifest. Production manifests should be generated by your release pipeline/backend and served over HTTPS.

## Production backend
The package deliberately does not invent a fake cloud server. The `IUpdateProvider` boundary allows the eventual SL backend/CDN to be connected without rewriting the game-side update architecture.
